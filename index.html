A gesture-controlled driving system using hand movement recognition, computer vision, ROS2 communication, and a simulated car environment.

Project Overview

This project demonstrates a hand movement car control system developed for 41118 AI in Robotics. The system uses webcam-based hand gesture recognition to classify user gestures and convert them into driving commands.

Recognised gestures are published through ROS2 topics and used to control a simulated driving environment. A web-based GUI displays the live hand tracking feed, driving status, current command, and simulated car view.

The project combines computer vision, machine learning, ROS2 communication, simulation, and user interface development into one integrated robotics system.

Hand Gesture Recognition

The gesture recognition subsystem uses webcam input and hand landmark detection to classify hand poses. These gestures are converted into commands such as moving forward, turning, stopping, or selecting a target block.

Driving Simulation

The driving subsystem receives gesture commands and applies them to a simulated car environment. The system allows the car to respond to recognised hand movements and move toward selected coloured targets.

ROS2 Integration

ROS2 topics are used to connect the gesture recognition node, driving environment, and GUI. This modular structure allows each subsystem to run independently while communicating through published messages.

Example topics:

  • /gesture/name
  • /gesture/command
  • /gesture/debug_image
  • /driving/status
  • /driving/debug_image

GUI Dashboard

Final Outcome

The final system allows a user to control a simulated car using recognised hand gestures. The gesture recognition node identifies the hand pose, publishes the matching command, and the driving environment responds by updating the car's movement or target.

The GUI acts as the visual interface for the system, showing both the hand tracking debug view and the simulated driving environment. This makes it easier to understand the relationship between user input, ROS2 messages, and vehicle behaviour.
